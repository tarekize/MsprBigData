\chapter*{Résumé}
\addcontentsline{toc}{chapter}{Résumé}

Ce mémoire présente la conception et le développement d'un système complet de prédiction des tendances électorales par indicateurs socio-économiques, réalisé dans le cadre d'une Preuve de Concept (POC) pour la société \textbf{Electio-Analytics}. Le périmètre géographique retenu est la région \textbf{Nouvelle-Aquitaine}, regroupant \textbf{12 départements} et \textbf{627 cantons}.

Le projet repose sur un pipeline de préparation des données en 9 phases — depuis le chargement de sources hétérogènes (CSV, Excel, NoSQL) jusqu'à un jeu final de \textbf{40\,000 lignes à 171 colonnes} — et met en \oe{}uvre cinq algorithmes de classification supervisée sur une variable cible construite de manière \textit{synthétique} à partir de 27 indicateurs delta socio-économiques. La cible comporte \textbf{5 classes à distribution réaliste asymétrique} : Crise (\pct{10}), Déclin (\pct{20}), Stable (\pct{40}), Croissance (\pct{20}), Boom (\pct{10}).

Le modèle le plus performant est \textbf{HistGradientBoosting}, avec une accuracy de \textbf{\pct{82,11}} et un F1-Score de \textbf{\pct{82,10}} sur le jeu de test. Les prédictions électorales s'appuient sur une logique \textbf{multi-candidats} mettant en concurrence les \textbf{12 candidats du 1\textsuperscript{er} tour 2022}, regroupés en 5 orientations politiques. Appliquées aux 12 départements de la Nouvelle-Aquitaine, elles affichent une précision départementale de \textbf{\pct{75,0} (9 sur 12)}.

L'interface utilisateur est développée en \textbf{React 19} (TanStack Router, TanStack Query, Recharts, Framer Motion) et expose les prédictions des cinq modèles à trois niveaux géographiques.

\bigskip
\noindent\textbf{Mots-clés :} Big Data, Machine Learning, Prédiction électorale, HistGradientBoosting, ETL, Delta Lake, React, Nouvelle-Aquitaine, indicateurs socio-économiques, 12 candidats 2022.

%% ── Abstract ─────────────────────────────────────────────────────────────────
\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

This thesis presents the design and development of a complete electoral trend prediction system based on socio-economic indicators, built as a Proof of Concept (POC) for \textbf{Electio-Analytics}. The geographic scope is \textbf{Nouvelle-Aquitaine}, comprising 12 departments and 627 cantons.

The project relies on a 9-phase data pipeline — from loading heterogeneous sources (CSV, Excel, NoSQL) to a final 40,000-row × 171-column dataset — and trains five supervised classification algorithms on a \textit{synthetically constructed} target variable derived from 27 socio-economic delta indicators. The target uses \textbf{5 classes with a realistic asymmetric distribution}: Crise (10\%), Déclin (20\%), Stable (40\%), Croissance (20\%), Boom (10\%).

The best performing model is \textbf{HistGradientBoosting}, reaching \textbf{82.11\%} accuracy and \textbf{82.10\%} F1-Score on the test set. Electoral predictions use a \textbf{multi-candidate approach} pitting all \textbf{12 first-round 2022 candidates} against each other across 5 political orientation blocs. When applied at the departmental level and compared against the actual 2022 presidential results, the predictions achieve \textbf{75.0\% accuracy (9 out of 12)} departments correctly classified.

\bigskip
\noindent\textbf{Keywords:} Big Data, Machine Learning, Electoral prediction, HistGradientBoosting, ETL, Delta Lake, React, Nouvelle-Aquitaine, socio-economic indicators, 12 candidates 2022.

Face à un marché électoral de plus en plus compétitif, la société souhaite se doter d'une capacité de \textbf{prévision des tendances électorales à moyen terme}, sur un horizon de un à trois ans, en s'appuyant sur des indicateurs socio-économiques mesurables : chômage, sécurité, pauvreté, démographie, dynamisme économique des territoires.

Avant tout investissement à grande échelle, Electio-Analytics a souhaité valider cette approche par une \textbf{Preuve de Concept (POC)}, confiée à notre équipe d'étudiants en fin de cursus expert à l'EPSI.

\section{Indicateurs delta — les features ML}

L'originalité du projet réside dans l'utilisation de \textbf{27 variables delta} (\code{delta\_*}) plutôt que de valeurs absolues. Chaque variable delta représente la variation relative entre deux mesures :

\begin{equation}
  \delta_{\text{col}} = \frac{V_{\text{récent}} - V_{\text{ancien}}}{V_{\text{ancien}} + \varepsilon}
  \label{eq:delta}
\end{equation}

où $\varepsilon = 10^{-9}$ évite la division par zéro. Ces variables capturent la \textbf{dynamique} du territoire plutôt que son état statique.

\begin{lstlisting}[caption={Extraction automatique des 27 features delta — ML notebook}]
feature_cols = [col for col in df.columns if col.startswith('delta_')]
X = df[feature_cols].copy()
print(f"Nombre de features : {len(feature_cols)}")
# Output : Nombre de features : 27
\end{lstlisting}

\section{Variable cible — construction synthétique à 5 classes}

\begin{infobox}[Point méthodologique clé : variable cible synthétique à 5 classes]
La variable cible du modèle ML n'est \textbf{pas directement} le résultat électoral historique. Elle est construite de manière \textbf{synthétique} à partir d'un score économique composite calculé sur les 27 variables delta, avec une \textbf{distribution réaliste asymétrique} reflétant la répartition territoriale réelle : majorité en situation stable, minorités aux extrêmes.
\end{infobox}

La construction se déroule en cinq étapes dans le notebook ML (étape 1) :

\begin{lstlisting}[caption={Construction de la variable cible à 5 classes — distribution réaliste asymétrique}]
# 1. Normalisation des 27 features
X_normalized = (X - X.mean()) / (X.std() + 1e-8)

# 2. Selection des 9 indicateurs economiques (pop, emplt, act, log)
economic_indicators = [col for col in feature_cols
    if any(x in col.lower() for x in ['pop', 'emplt', 'act', 'log'])]
# => 9 indicateurs selectionnes

# 3. Score composite (poids aleatoires, seed=42)
np.random.seed(42)
weights = np.random.rand(len(available_economic))
weights = weights / weights.sum()
base_score = (X_normalized[available_economic] * weights).sum(axis=1)

# 4. Bruit Gaussien (sigma=0.08) + normalisation finale
noise = np.random.normal(0, 0.08, len(base_score))
final_score = base_score + noise
final_score = (final_score - final_score.mean()) / final_score.std()

# 5. Decoupage en 5 classes — distribution REALISTE non-equilibree
#    Crise      : 10% — zones en grave difficulte (rares)
#    Declin     : 20% — zones qui perdent de vitesse
#    Stable     : 40% — situation normale (majorite)
#    Croissance : 20% — zones dynamiques
#    Boom       : 10% — zones en forte expansion (rares)
q1 = final_score.quantile(0.10)   # seuil Crise/Declin
q2 = final_score.quantile(0.30)   # seuil Declin/Stable
q3 = final_score.quantile(0.70)   # seuil Stable/Croissance
q4 = final_score.quantile(0.90)   # seuil Croissance/Boom

y_labels = pd.cut(
    final_score,
    bins=[final_score.min()-1, q1, q2, q3, q4, final_score.max()+1],
    labels=['Crise', 'Declin', 'Stable', 'Croissance', 'Boom'],
    ordered=False
)
\end{lstlisting}

\section{Mapping économique vers orientation politique — 12 candidats}

Les prédictions économiques (5 classes) sont converties en prédictions électorales pour les \textbf{12 candidats du 1\textsuperscript{er} tour de la présidentielle 2022} via une logique en trois étapes :

\begin{enumerate}
  \item Chaque classe économique est associée à une \textbf{orientation politique} via \code{ECO\_TO\_ORIENTATION} ;
  \item Les probabilités des 5 classes (issues du modèle ML) sont agrégées par orientation pour obtenir une \textbf{probabilité de bloc} ;
  \item Le score de chaque candidat est calculé comme : $\text{score} = P(\text{orientation}) \times \text{poids\_intra\_bloc}$ où le poids intra-bloc est la part nationale du candidat dans son bloc.
\end{enumerate}

\begin{lstlisting}[caption={Mapping économique vers orientation politique — ML notebook}]
# Mapping eco_class -> orientation politique
ECO_TO_ORIENTATION = {
    "Crise":      "ExtremeDroite",   # vote protestataire
    "Declin":     "Droite",          # vote conservateur
    "Stable":     "Centre",          # vote de continuite
    "Croissance": "Gauche",          # vote progressiste
    "Boom":       "ExtremeGauche",   # vote radical/alternatif
}

# 12 candidats avec leur orientation et resultat national 1er tour 2022 (%)

\begin{infobox}[Logique probabiliste — sans hardcoding]
Le vainqueur n'est pas déterminé par une règle fixe mais par les probabilités ML : \textbf{la somme des probabilités de toutes les classes d'une même orientation donne la probabilité du bloc}, puis chaque candidat reçoit un score proportionnel à son poids intra-bloc. \begin{lstlisting}[caption={Chargeur générique avec détection de clé géographique}]
def load_indicator(path, file_name):
    full_path = os.path.join(path, file_name)
    if file_name.endswith('.csv'):
        try:
            df = pd.read_csv(full_path, sep=';', encoding='utf-8',
                             low_memory=False)
        except UnicodeDecodeError:
            df = pd.read_csv(full_path, sep=';', encoding='latin1',
                             low_memory=False)
    else:
        df = pd.read_excel(full_path,
                           engine='openpyxl' if file_name.endswith(
                               '.xlsx') else None)
    # Recherche de la cle geographique
    for col in df.columns:
        c_up = str(col).upper()
        if any(x == c_up for x in ['CODGEO','CODE INSEE','COM',
                                    'CODE_COMMUNE','INSEE_POP']):
            df['CODGEO'] = (df[col].astype(str)
                            .str.replace('.0', '', regex=False)
                            .str.zfill(5))
            print(f"OK {file_name}: {df.shape[0]} lignes (Cle: {col})")
            break
    return df
\end{lstlisting}

\subsection{Analyse des erreurs — trois départements mal prédits}

Les trois départements incorrectement prédits — \textbf{Creuse}, \textbf{Dordogne} et \textbf{Lot-et-Garonne} — partagent un profil commun : territoires ruraux à faible densité de population, économie fragilisée, vieillissement démographique et départ des actifs. Tous ont donné la première place à Le Pen (RN) au 1\textsuperscript{er} tour 2022.

\textbf{Explication structurelle de l'erreur :}

\begin{itemize}
  \item La variable cible est \textbf{synthétique} — elle encode un score économique composite, pas directement le vote. Ces trois départements présentent un score économique intermédiaire (classe \textit{Stable} prédominante dans la distribution de probabilités), ce qui oriente la prédiction vers le bloc Centre (Macron).

  \item \textbf{Logique probabiliste multi-candidats} : même dans des zones économiquement fragiles, si la probabilité cumulée du bloc \textit{Centre} (classe Stable) reste dominante dans la distribution des 5 classes, Macron l'emporte. Le basculement vers Le Pen (RN) nécessiterait que la probabilité de la classe \textit{Crise} (→ ExtremeDroite) dépasse la probabilité de la classe \textit{Stable} (→ Centre), ce qui n'est pas le cas ici.

  \item \textbf{Prédiction par moyenne de features par département} : le calcul \code{group\_X.mean()} lisse les hétérogénéités intra-départementales. Des cantons très défavorisés coexistent avec des zones plus stables, ce qui atténue le signal \textit{Crise/Déclin}.

  \item \textbf{Poids intra-bloc ExtremeDroite} : dans le bloc Extrême Droite, Le Pen (RN) détient \pct{71,7} du poids — mais ce score élevé ne suffit pas si la probabilité globale du bloc reste inférieure à celle du Centre.
\end{itemize}

\chapter*{Conclusion et recommandations}
\addcontentsline{toc}{chapter}{Conclusion et recommandations}

\section*{Bilan du POC}

Ce projet a permis de concevoir et livrer une Preuve de Concept complète de prédiction électorale par indicateurs socio-économiques pour Electio-Analytics.

\textbf{Pipeline de données.} Un pipeline en 9 phases a été développé sur les données de la Nouvelle-Aquitaine, faisant passer le volume de 756 lignes électorales brutes à \textbf{40\,000 lignes augmentées à 171 colonnes}. La chaîne complète intègre : chargement multi-format, fusion CODGEO, augmentation par bruit Gaussien, augmentation temporelle (3 périodes), perturbation aléatoire, normalisation MinMax, et export CSV + Parquet. TinyDB s'est substitué à MongoDB (non disponible) et l'export Delta Lake a échoué sur un problème de schéma.

\textbf{Modèle prédictif.} Cinq classificateurs ont été entraînés sur une variable cible \textbf{synthétique à 5 classes, à distribution réaliste asymétrique} (Crise 10\%, Déclin 20\%, Stable 40\%, Croissance 20\%, Boom 10\%). \textbf{HistGradientBoosting} est le meilleur modèle : \textbf{\pct{82,11}} d'accuracy, F1 = \textbf{\pct{82,10}}, entraîné en ~11 secondes grâce aux optimisations (HistGB vs GradientBoosting séquentiel, LinearSVC vs SVC rbf, 3-fold vs 5-fold).

\textbf{Prédiction multi-candidats.} La logique de prédiction électorale a été entièrement repensée : les 12 candidats du 1\textsuperscript{er} tour 2022 sont mis en concurrence via un mécanisme d'orientation politique + pondération intra-bloc, \textbf{sans hardcoding de règles fixes}. Chaque vainqueur prédit émerge des probabilités ML. Cette approche révèle des gagnants variés selon les territoires (Mélenchon en Charente, Pécresse à Bordeaux 1, Poutou à Saint-Vaury).

\textbf{Interface utilisateur.} Un dashboard React 19 expose les prédictions des cinq modèles à trois niveaux géographiques (Région / 12 Départements / 627 Cantons) avec spectre politique animé, top 5 candidats, et page d'analyse approfondie.

\section*{Limites identifiées}

\begin{description}
  \item[Variable cible synthétique.] La cible ML n'est pas construite sur les vrais résultats électoraux historiques mais sur un score économique simulé. Ce choix permet d'atteindre 80\%+ d'accuracy, mais introduit un biais structurel : le modèle prédit un état économique et non directement le vote.

  \item[75\% de précision départementale.] Trois départements (Creuse, Dordogne, Lot-et-Garonne) sont incorrectement prédits — tous ont voté Le Pen (RN) en 2022 mais le modèle les classe en zone Stable → Centre. La variable cible synthétique ne capte pas les dynamiques de protestation électorale déconnectées du score économique agrégé.

  \item[Données partiellement chargées.] Plusieurs fichiers sources (Revenus, Diplôme, Délinquance détaillée) n'ont pas pu être intégrés faute de clé géographique détectable.

  \item[Delta Lake non fonctionnel.] L'export au format Delta Lake a échoué (\texttt{Field Année not found in schema}).
\end{description}

\section*{Recommandations pour le passage en production}

\begin{enumerate}
  \item \textbf{Variable cible réelle.} Construire la cible directement sur les résultats électoraux historiques (vainqueur par canton 2012/2017) encodés en orientation politique — ce qui élimine le besoin de la cible synthétique.

  \item \textbf{Enrichissement des blocs politiques.} Intégrer les résultats des élections législatives et européennes pour affiner les poids intra-bloc et les associer à des dynamiques territoriales observées.

  \item \textbf{Intégration complète des sources.} Harmoniser les fichiers Revenus, Diplôme et Délinquance détaillée pour les rendre compatibles avec la jointure CODGEO.

  \item \textbf{Corriger l'export Delta Lake.} Renommer la colonne \code{Année} en \code{annee} (ASCII, snake\_case) avant l'écriture, conformément au schéma PyArrow attendu par \texttt{delta-rs}.

  \item \textbf{Déploiement MongoDB.} Provisionner une instance MongoDB (Atlas ou Docker) pour remplacer TinyDB et bénéficier des capacités de requêtage avancées.

  \item \textbf{API REST backend.} Remplacer le fichier \texttt{predictions.json} statique par une API FastAPI ou Flask avec mise en cache Redis, permettant des requêtes dynamiques par département ou canton.

  \item \textbf{Extension géographique.} Répliquer le pipeline sur les 12 régions métropolitaines. La structure modulaire (\code{load\_indicator()}, \code{calculate\_delta()}) est déjà généralisable.

  \item \textbf{Validation prospective.} Lors de la prochaine échéance électorale (législatives 2027), confronter les prédictions aux résultats réels pour mesurer le \textit{model drift} et déclencher un réentraînement si l'accuracy descend sous \pct{70}.
\end{enumerate}

\section*{Architecture du script \texttt{generate\_visualisations.py}}

Le script produit 7 graphiques PNG dans \texttt{public/data/charts/} via Matplotlib et Seaborn, avec une palette sombre personnalisée.

\begin{lstlisting}[caption={Palette et style sombre partagé}]
PALETTE = {
    'bg':      '#0f1117',   # Fond global
    'card':    '#1a1d2e',   # Fond axes
    'primary': '#6366f1',   # Barres principales (indigo)
    'accent':  '#a78bfa',   # Barres secondaires (violet)
    'text':    '#e2e8f0',   # Texte
    'muted':   '#64748b',   # Labels secondaires
    'green':   '#10b981',   # Positif
    'amber':   '#f59e0b',   # Attention
    'rose':    '#f43f5e',   # Erreur / Extreme droite
}

def apply_dark_style(fig, ax_list=None):
    fig.patch.set_facecolor(PALETTE['bg'])
    for ax in (ax_list or fig.axes):
        ax.set_facecolor(PALETTE['card'])
        ax.tick_params(colors=PALETTE['muted'], labelsize=9)
        for spine in ax.spines.values():
            spine.set_edgecolor('#2d3149')

def save(fig, name):
    fig.savefig(os.path.join(CHARTS_DIR, name),
                dpi=140, bbox_inches='tight',
                facecolor=fig.get_facecolor())
    plt.close(fig)
